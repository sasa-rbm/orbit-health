OSDR

Open Science Data Repository Reference

NASA's repository for biological and physiological spaceflight research. This prototype uses OSDR as study context and mapping guidance; it does not query OSDR during an astronaut check-in.

  • Relevant context: cardiovascular, metabolic, bone, muscle, immune, and sleep research
  • Production teams should pin the exact dataset, version, units, and inclusion criteria

METEO

Meteomatics Weather API Python backend

The dashboard calls the local FastAPI relay, which requests global_rad:W for an Earth coordinate. Credentials stay on the backend; the result is environmental context only and is not connected to the astronaut's dosimeter or absorbed radiation dose.

  • Backend endpoint: /api/environment/radiation
  • Cached and stale-value handling are implemented

How Readings Map to Sources

1. Measure in flight. Heart rate, blood pressure, SpO₂, temperature, glucose, sleep, pain, and symptoms can be recorded onboard without a lab.

2. Establish the personal 1G baseline. The 1G record stores the astronaut's pre-flight or ground-analog normal range. SSM-aligned variable names preserve units and collection context.

3. Compare 0G telemetry continuously. The monitor compares each incoming spaceflight value with that personal baseline, then assigns OK, watch, or alert drift levels. OSDR provides study metadata and analog context; it does not replace flight medicine thresholds.

4. Flag by hazard. Readings link to known spaceflight hazards: fluid shift and SANS, cardiovascular deconditioning, bone and muscle loss, space motion sickness, hypoglycemia, immune dysregulation, and sleep deficit.

5. Escalate. Alert-level findings call for the flight surgeon now. Watch-level findings go into the next scheduled report and trigger a recheck.

6. Trace. Record the measurement source and device in the crew health record. Mission control can perform deeper OSDR study review and hardware traceability outside the offline astronaut workflow.

Limits: Ranges here are illustrative placeholders, not validated flight criteria. Before operational use, replace them with thresholds reviewed by NASA flight medicine and cite the exact OSDR or PSI dataset for each one.
